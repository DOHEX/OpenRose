[#39：修正未连接耳机页布局、传输不可用状态与选择弹窗容器](https://github.com/DOHEX/OpenRose/issues/39)

## What to build

控制传输明确不可用且未连接耳机时，两套界面风格的首页直接显示宿主提供的原因及“查看连接与运行状态”入口，隐藏顶栏右上角“添加耳机”、附近设备列表与空列表提示、扫描按钮。用户可以查看实际运行状态，而不会被引导进入无法完成的扫描或添加流程。

状态分支由真实传输状态决定，适用于当前 Linux、Windows 宿主；权限不足、蓝牙关闭和传输可用等分支保留现有恢复与手动扫描流程。本票可以沿用当前布局独立完成，紧凑单列的布局参数由同一父规格的布局子票处理。

## Acceptance criteria

- [ ] 使用宿主提供的权限与传输状态，先保留权限不足、权限拒绝及蓝牙关闭的可恢复流程；权限条件允许而控制传输仍报告 `TransportAvailability.Unavailable` 时才呈现平台不可用视图。显示实际原因，不按 Linux/Windows 名称硬编码分支，不伪造传输就绪。
- [ ] 两套风格的顶栏“添加耳机”、附近设备列表及其空列表提示、扫描按钮均不渲染，也不保留对应键盘焦点；首页保留明确原因与“查看连接与运行状态”入口。
- [ ] 点击状态入口可到达现有运行状态详情并正常返回；不新增诊断页面或改变系统页固定诊断入口的既有职责。
- [ ] 传输不可用状态切换为可用后恢复既有添加、附近设备与手动扫描入口；仅明确点击才产生相应操作回调。渲染不可用状态、打开详情或切换界面风格不请求权限、不启动扫描或连接、不写入设备设置。
- [ ] 权限不足仍提供权限恢复操作，蓝牙关闭仍提供打开蓝牙设置操作；它们不被替换为平台不可用视图。覆盖权限 REQUIRED/DENIED 与传输 Unavailable 同时出现的组合，确认恢复操作仍可用。传输可用但尚未扫描、扫描中、连接中、失败及已连接流程保留既有行为。
- [ ] 以公开 `OpenRoseApp` 为主要验证入口，复用合成状态、语义与键盘操作及回调观察；两套风格均验证原因、入口显隐、详情导航和不可用/可用状态切换，复用已有平台与扫描回归，不新增页面或组件测试入口。
- [ ] 更新旧“传输不可用时仍显示禁用扫描按钮”的测试预期，明确断言该按钮及顶栏添加、附近列表/空状态不存在；保持可恢复状态的既有操作验证。
- [ ] 查看两套风格 × 浅色/深色的 360/420dp 窄屏和 1280dp 宽屏不可用首页截图，检查原因与状态入口清晰可读、无重复空列表或禁用扫描提示；截图与语义断言互相补充。
- [ ] 更新不可用分支的旧呈现规则与验证记录；运行受影响的共享 UI 测试与相关回归，完成 Android 调试包和本地 Linux 桌面分发构建。外壳受改动时检查本地顶栏与缩放。
- [ ] 不接入 BlueZ、Windows 蓝牙或控制传输回调，不修改协议、控制会话与持久化设置；Linux/Windows 真实传输分别继续由 #31/#32 跟踪。
