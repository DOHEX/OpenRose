[#39：修正未连接耳机页布局、传输不可用状态与选择弹窗容器](https://github.com/DOHEX/OpenRose/issues/39)

## What to build

选择组件风格或使用同一选择弹窗容器时，选项列表与弹窗表面协调，消除明显的矩形底色。Material 3 弹窗内单选行使用透明容器，使父弹窗表面透出；Miuix 保持相应默认库组件。选择项、选中状态、关闭方式与回调行为继续可靠可用。

本票独立交付实际选择流程的外观修正、交互回归和视觉证据，不依赖首页布局或平台不可用状态的调整。

## Acceptance criteria

- [ ] Material 3 AlertDialog 内的单选 ListItem 使用透明容器，选项区域与父弹窗表面协调，没有突兀的矩形底色；局部例外不扩展到普通 ListItem、全局配色、形状或字体。
- [ ] 保留各库默认弹窗、单选控件、字体、形状与主题配色；Miuix 使用相应默认组件，两个界面风格保留可辨认的各自观感。
- [ ] 修正覆盖实际使用同一弹窗容器的选择流程，不对“组件风格”文案单独打补丁；至少复核组件风格选择器及一个实际复用该容器的代表性选择流程。
- [ ] 原有选项、已确认值与请求值的区别、未知值语义、选中状态和关闭方式保持正确；取消或关闭不提交，明确选择按原有语义产生回调，未获设备确认前不把请求值冒充确认值。
- [ ] 在控制期间切换界面风格保持控制会话、设备状态、导航、滚动位置、草稿与待确认命令的既有生命周期；不触发扫描、重连、重复发送或不相关设置写入。
- [ ] 以公开 `OpenRoseApp` 为主要入口，复用合成状态、语义及键盘操作和回调观察验证打开、选择、关闭与跨风格行为；既有低层选择器测试作为回归，不新增页面或组件测试入口。
- [ ] 查看两套风格 × 浅色/深色的组件风格选择器打开状态与代表性复用场景截图，覆盖窄屏和宽屏，检查选项/弹窗底色、文字、选中态及控件均清晰，无溢出、裁切或重叠。外观协调必须通过看图确认。
- [ ] 保留默认触控目标、可辨认标签和单选语义；Tab/Shift+Tab 可到达可见控件，Enter/Space 按既有交互操作，Escape 按已有层级关闭或返回。
- [ ] 同步补充默认外观覆盖白名单中的“弹窗内单选行透明容器”局部规则及视觉验证记录；运行受影响共享 UI 测试和既有选择器/会话连续性回归，完成 Android 调试包与本地 Linux 桌面分发构建，并在本地桌面宿主检查弹窗外观。
- [ ] 不新增界面风格、动态取色、强调色选择、持久化设置、协议行为或传输实现；截图不作为真实耳机或系统呈现验收证据。
