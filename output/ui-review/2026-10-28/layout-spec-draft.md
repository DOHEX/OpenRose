## Problem Statement

OpenRose 的未连接耳机页在桌面宽屏上内容稀疏，标题上方留白偏大，说明、分隔线和扫描按钮横向展开，缺少适合少量内容的比例和对齐关系。Miuix 的部分单句说明被独立卡片包成细长白条；Material 3 的选择弹窗中，选项列表的矩形底色与弹窗表面明显分离。用户能辨认组件，却难以从页面组合中获得清楚、协调的信息层次。

当前 Linux 桌面尚未接入耳机控制传输，但首页同时显示未实现原因、附近设备空列表和禁用扫描按钮，容易让用户以为只需等待或重新扫描即可连接耳机。

## Solution

保留 Miuix 与 Material 3 各自的默认组件观感，修正未连接页的布局比例、说明与分组的容器用法，以及选择弹窗的表面协调。

未连接时采用紧凑的单列内容区，宽屏内居中、内部左对齐，收紧顶部留白；连接说明、设备列表和操作保持清晰边界，扫描按钮使用常规宽度。控制传输不可用时，首页只呈现明确原因和“查看连接与运行状态”入口，隐藏添加、附近设备列表和扫描入口。传输可用时沿用手动扫描与连接流程，权限不足、蓝牙关闭等可恢复状态继续提供相应操作。

已连接首页的设备信息、降噪快捷操作、功能入口及宽屏双列布局继续沿用。两套界面风格表达相同的信息层级，各自使用合适的默认组件与表面。

## User Stories

1. 作为桌面用户，我希望未连接耳机时看到紧凑的内容区，以便少量信息仍有合适的页面比例。
2. 作为桌面用户，我希望未连接页的内容区在主内容区域内居中，以便大窗口中的左右留白保持协调。
3. 作为用户，我希望内容区内部的说明、列表和操作左对齐，以便顺畅阅读并找到下一步操作。
4. 作为用户，我希望未连接页顶部没有过量空白，以便更早看到连接状态和可用操作。
5. 作为尚未连接耳机的用户，我希望连接说明、附近设备和扫描操作形成清楚的顺序，以便理解连接流程。
6. 作为用户，我希望扫描按钮使用符合文案和默认控件尺寸的常规宽度，以便按钮不会占据整条宽屏内容区。
7. 作为窄屏用户，我希望单列内容区能够随可用宽度收缩，以便文字和操作保持可读且没有横向溢出。
8. 作为用户，我希望普通说明直接排版，以便不会把细长白条误认为独立卡片或输入控件。
9. 作为用户，我希望卡片包裹完整的信息组，以便视觉边界能反映内容关系。
10. 作为 Miuix 用户，我希望调整后的分组仍保持 Miuix 的组件观感，以便页面与所选界面风格一致。
11. 作为 Material 3 用户，我希望调整后的分组仍保持 Material 3 的组件观感，以便页面与所选界面风格一致。
12. 作为切换界面风格的用户，我希望两套风格表达相同的信息与操作层级，以便不必重新理解连接流程。
13. 作为选择组件风格的用户，我希望弹窗中的选项与弹窗表面协调，以便选项列表不会像额外嵌入的矩形面板。
14. 作为用户，我希望采用相同选择弹窗容器的其他选项也获得一致的修正，以便同类选择操作有协调的外观。
15. 作为用户，我希望弹窗保留清楚的选项、选中状态和关闭方式，以便外观调整后仍能可靠完成选择。
16. 作为用户，我希望应用保留所选界面风格的默认字体、形状和主题配色，以便本次调整不会改变整套外观体系。
17. 作为浅色或深色模式用户，我希望内容分组与弹窗在两种模式下都协调可读，以便切换明暗模式后仍能分辨信息层次。
18. 作为当前 Linux 客户端用户，我希望首页直接解释耳机控制传输尚未实现，以便理解目前可用能力。
19. 作为使用控制传输不可用平台的用户，我希望看到该平台提供的实际原因，以便界面不会把所有平台问题都归结为未发现耳机。
20. 作为控制传输不可用时的用户，我希望首页隐藏添加耳机入口，以便不会进入无法完成的添加流程。
21. 作为控制传输不可用时的用户，我希望首页隐藏附近设备列表和空列表提示，以便不会误以为应用正在正常寻找耳机。
22. 作为控制传输不可用时的用户，我希望首页隐藏扫描按钮，以便可见操作都具有当前可执行的意义。
23. 作为控制传输不可用时的用户，我希望通过“查看连接与运行状态”查看详情，以便进一步了解当前运行条件。
24. 作为平台传输可用的用户，我希望首页仍展示附近设备与手动扫描入口，以便主动开始连接耳机。
25. 作为缺少蓝牙权限的用户，我希望仍能看到原因和授予权限操作，以便解决可恢复的问题。
26. 作为系统蓝牙关闭的用户，我希望仍能看到原因和打开蓝牙设置的操作，以便恢复连接条件。
27. 作为正在扫描的用户，我希望保留扫描进度和停止扫描操作，以便控制发现过程。
28. 作为连接耳机的用户，我希望保留设备识别、连接进度、取消、失败说明及重试流程，以便布局调整后仍能完成原有操作。
29. 作为用户，我希望打开页面、调整窗口或切换界面风格时不会自动启动扫描或连接，以便操作仍由我的明确选择触发。
30. 作为已连接用户，我希望保留设备信息、降噪快捷操作和功能入口，以便继续使用已熟悉的耳机控制。
31. 作为已连接的宽屏用户，我希望保留既有双列布局，以便充分利用设备信息与控制内容的展示空间。
32. 作为调整窗口大小的用户，我希望保留既有侧栏、底栏和已连接页面的响应式切换规则，以便导航和控制布局保持一致。
33. 作为切换界面风格的用户，我希望控制连接、设备确认状态和正在执行的命令保持连续，以便调整外观不会打断耳机控制。
34. 作为键盘用户，我希望可见控件仍可通过 Tab、Shift+Tab、Enter、Space 和 Escape 操作，以便布局调整后仍能完成导航与选择。
35. 作为依赖辅助功能的用户，我希望保留导航、按钮和单选控件的语义及可辨认标签，以便理解和操作页面。
36. 作为触控用户，我希望按钮和选择项保留默认可操作区域，以便常规宽度按钮仍容易点击。

## Implementation Decisions

- 调整共享界面模块中的未连接耳机页、页面内容布局策略、按界面风格实现的外壳操作区，以及说明、分组和选择弹窗的共用呈现。Android 与桌面宿主继续提供真实平台状态，不新增传输实现。
- 沿用公开 `OpenRoseApp` 的状态输入和操作回调契约；不为本次布局修改新增产品配置、持久化字段或独立控制会话，不要求改变公开入口签名。
- 根据是否存在当前控制连接区分首页布局。未连接页使用紧凑单列，宽屏主内容区内居中、内部左对齐；已连接页沿用既有设备与控制布局。具体最大宽度、页面边距和间距由实现通过截图复核确定，不新增用户设置。
- 收紧未连接页顶部留白，使用所选库合适的默认外壳或布局方式，不以自定义字体、形状或全局配色覆盖实现视觉压缩。
- 说明、设备列表和操作按内容关系分组。普通说明不单独套卡片，卡片承载完整信息组。两套风格共享信息层级，不要求采用相同表面或卡片结构。
- 扫描操作使用常规宽度按钮，宽度遵循文案、库默认内边距及可用空间；保留默认可操作区域和窄屏可用性。本决定替换旧“扫描按钮全宽”的规则。
- 对控制传输明确不可用的未连接状态，两套界面风格的首页均隐藏顶栏右上角“添加耳机”动作、附近设备列表与空状态提示、扫描按钮；显示宿主提供的实际原因及“查看连接与运行状态”入口，复用现有详情导航。
- 不按操作系统名称硬编码不可用视图。当前 Linux、Windows 宿主均报告传输不可用，适用同一状态规则；后续宿主报告传输可用时自然恢复既有扫描流程。本规格不实现该后续传输能力。
- 保持传输不可用、权限不足、蓝牙关闭及传输可用但未扫描等状态的区别。权限不足与蓝牙关闭继续提供各自恢复操作，不被简化为平台不可用视图。
- 传输可用时沿用手动扫描、停止、候选设备识别、连接、取消、失败与重试语义；渲染、窗口尺寸变化和界面风格切换不得触发这些操作回调。
- 继续采用各库自带的选择弹窗与单选控件。Material 3 AlertDialog 内的单选 ListItem 使用透明容器，使父弹窗表面透出；该局部例外仅限弹窗内选项行，是对旧默认外观覆盖白名单的补充，不改变普通 ListItem、全局配色或形状。Miuix 继续采用相应默认库组件。
- 保留原有选项、已确认值与请求值的区别、未知值语义、关闭方式、选择回调及界面风格切换行为。共享弹窗容器的修正应覆盖实际使用该容器的选择流程，不能仅对“组件风格”文本做特例。
- 沿用首页 1120dp、其他页面 800dp 的既有最大宽度基线；紧凑未连接页可以采用更小上限。保留已连接内容 680dp 双列断点和 900dp 导航断点。
- 遵守既有 ADR 对界面风格切换、控制会话所有权和平台适配边界的要求。保留导航、滚动位置、草稿、当前设备状态和待确认命令的既有生命周期；不因容器调整重连、重新发送或清空状态。
- 实施时同步更新受本规格替换的旧布局规则、对应测试预期与视觉验证记录。其余已确认的页面职责、平台内容显隐及诊断分层继续沿用。

## Testing Decisions

- 用户已确认测试边界：以现有公开 `OpenRoseApp` 为主要入口，复用现有离屏 Compose 测试场景，输入合成 `ControlState`，通过真实语义及键盘操作、可见布局边界和回调观察验证外部行为；通过同一入口的截图复核布局与弹窗表面，不新增页面或组件测试入口。
- 不为每页、每个容器或每种平台新增测试专用产品接口，不以具体组件类型、内部 Modifier 顺序或私有状态实现作为验收依据。需要复用辅助断言时，扩展现有测试工具即可。
- 主要验证共享界面模块。参考既有首页扫描、平台适用性、已连接首页、导航和默认样式交互测试；沿用真实公开入口测试优先的方式。已有低层选择器测试可作为行为回归，不替代完整页面验证。
- 关键行为矩阵：两套界面风格下分别覆盖传输不可用、权限不足、蓝牙关闭、可扫描空列表、发现候选设备、扫描中、连接中、失败和已连接状态，断言入口显隐、原因文本、详情导航及操作回调次数符合状态。
- 更新旧测试中“传输不可用时仍显示禁用扫描按钮”的预期：现在两套风格的顶栏“添加耳机”、附近列表及空状态提示、扫描按钮均应不存在；权限不足、蓝牙关闭等场景的恢复行为继续按既有约定验证。
- 验证不可用状态切换到可用状态后恢复扫描入口，且仅点击明确操作才产生回调；在不可用状态显示原因或打开详情时不请求权限、不启动扫描或连接。
- 使用用户可见几何关系验证宽屏未连接页保持单列、内容区居中且内部左对齐、扫描按钮不是整条宽屏内容宽度；不把尚未确定的像素常量写成产品契约。
- 复用现有截图与键盘检查方式。至少检查两套风格的浅色和深色、360/420dp 窄屏、1280dp 宽屏未连接可扫描与传输不可用首页，以及“组件风格”选择器打开状态；覆盖实际使用相同弹窗容器的代表性选择流程。设置、系统页若受共用分组修正影响，也纳入视觉复核。
- 视觉验收重点是顶部空白、内容宽度与对齐、说明与完整分组边界、按钮比例、弹窗表面协调，以及无裁切、重叠或横向溢出。语义测试无法证明底色协调，必须查看生成截图。
- 在已连接首页复核 679/680dp、导航复核 899/900dp 边界，确认既有单/双列与底/侧导航规则；不要求未连接页面在 680dp 切成双列。
- 保留现有键盘、辅助功能语义和选择器行为检查；验证 Tab/Shift+Tab 可到达可见控件，Enter/Space 可操作，Escape 按已有层级关闭或返回，隐藏入口不占焦点。继续复用既有控制会话连续性回归，不为无协议改动重复新增协议层测试。
- 运行受影响的共享 UI 测试及仓库既有相关回归，完成 Android 调试包与本地 Linux 桌面分发构建。若改动外壳布局，在现有本地桌面宿主检查窗口缩放、顶部区域与弹窗外观。
- 合成状态、离屏截图和本地构建只证明对应的布局与交互范围，不作为真实耳机连接、Linux/Windows 蓝牙控制、HyperOS 系统呈现或 Windows 运行验收的证据。

## Out of Scope

- Linux BlueZ 与 Windows 蓝牙传输实现及其真实耳机验收，分别由 #31、#32 跟踪。
- 调整 Android 优先的交付顺序，新增型号能力、协议命令、自动扫描或自动连接。
- 改变已连接首页的信息结构、降噪快捷操作、功能页职责、系统与设置页的内容归属或既有导航顺序。
- 全站视觉重设计、两套风格统一成同一种卡片外观、第三种界面风格、动态取色、强调色选择或新外观设置。
- 改变控制会话、命令队列、设备回读确认、未知值、待确认状态、系统集成及通知语义。
- 为这次修正新增领域术语、架构边界、数据库或持久化设置。

## Further Notes

- 本规格来自 2026-10-28 的两轮访谈，五项设计决定均已获用户明确确认：紧凑未连接布局、容器层次、不可用状态的信息优先级、单列对齐与常规宽度按钮、不可用状态隐藏入口。
- 本规格补充 [#33：三个顶级页面重设计](https://github.com/DOHEX/OpenRose/issues/33)，保留其页面职责、平台可见性和已连接布局，只替换本文明确列出的旧布局与容器规则；不重新打开既有 ADR。
- Linux 当前不可用来自桌面宿主尚未接入产品传输。已有研究读取不代表桌面产品适配完成，见 [#31](https://github.com/DOHEX/OpenRose/issues/31)；Windows 对应工作见 [#32](https://github.com/DOHEX/OpenRose/issues/32)。
- 交付应包含界面修改、必要的行为验证、复核过的截图和更新后的布局规则记录。不得把“截图生成成功”或“构建成功”单独作为视觉效果达标的结论。
