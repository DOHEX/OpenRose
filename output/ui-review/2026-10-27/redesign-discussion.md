# 三个顶级页面重设计访谈

状态：访谈已收敛，各轮设计决策已获用户确认。这里记录页面方案、参考事实和确认过程；正式规格按项目约定使用 GitHub Issues。本轮交付为设计记录与词汇更新，尚未实施页面改版。

正式规格已发布为 [#33：重设计耳机、系统与设置三页，并按平台显示内容](https://github.com/DOHEX/OpenRose/issues/33)，标记 `ready-for-agent`。GitHub 正文与发布草稿及标签已核对，后续实施以该规格为准。

## 最终页面结构

导航顺序为“耳机 / 系统 / 设置”，默认进入耳机页。Miuix 与 Material 3 各自使用库默认组件和外观，手机底栏、宽屏侧栏及首页双列沿用既有响应式布局。

| 页面 | 职责与信息层级 |
| --- | --- |
| 耳机 | 未连接时直接显示附近设备与手动扫描入口，权限、蓝牙、连接中、取消和失败在同页处理。连接后优先显示型号、控制连接状态、电量和降噪快捷操作；均衡器、触控、音频设置与设备详情通过列表入口进入。右上角连接菜单提供“断开控制连接”，断开后回到附近设备列表。 |
| 系统 | 仅显示本平台的状态摘要、未就绪原因与诊断入口。诊断为二级页面，承载已有详细状态与操作记录；相关错误处提供上下文入口。 |
| 设置 | 集中应用偏好和系统集成配置：界面风格、明暗模式、连接偏好，以及适用于当前平台的超级岛、焦点通知和模块显示时机。关于沿用设置底部的信息行。 |

耳机控制与应用偏好的边界已明确：“配置项集中到设置页”指应用及系统集成偏好，降噪、均衡器、触控等耳机能力控制保留在耳机页及其功能页。

系统呈现配置沿用当前设置页的默认组件呈现：超级岛一行显示当前值并点击选择，焦点通知为独立开关，仅模块模式显示模块触发时机；不再将这些配置放进系统状态页。

## 平台可见性

| 内容 | 普通 Android | 适用的 HyperOS | Windows / Linux |
| --- | --- | --- | --- |
| 三项主导航、外观、关于 | 显示 | 显示 | 显示 |
| 系统页的状态摘要 | 本平台蓝牙权限、蓝牙状态 | 蓝牙权限、蓝牙状态，以及模块与系统集成状态 | 本平台蓝牙与运行状态 |
| 诊断入口及内容 | 入口保留，内容限定本平台 | 入口保留，包含适用的集成状态 | 入口保留，内容限定本平台 |
| 超级岛、焦点通知、模块时机、融合设备中心相关内容 | 隐藏 | 按实际适用范围显示 | 隐藏 |
| 连接传输偏好，如强制使用 BLE | 按平台连接能力显示 | 按平台连接能力显示 | 按平台连接能力显示；当前未提供控制传输，不呈现无实际作用的偏好 |
| 耳机功能控制 | 按型号能力及真实设备状态 | 按型号能力及真实设备状态 | 按型号能力及真实设备状态；不因此新增桌面传输实现 |

平台不适用时隐藏相关设置和状态内容，不在其他平台显示 HyperOS 占位提示。平台适用但暂未就绪时仍保留配置并允许保存，系统页明确显示未就绪原因。隐藏配置不表示重置已保存的偏好；设备控制中的未知值仍明确显示为未知。

当前实现尚未在共享状态中明确区分平台适用性和集成就绪状态，也没有 HyperOS 识别逻辑。后续实现需取得可靠的平台与功能适用依据，不能仅凭模块是否已连接决定专属内容可见性，也不能用一条不可用原因文案代替平台判断。

## 已确认方向

2026-10-27，用户以 `$grill-with-docs` 提出参考 OppoPods 重设计三个页面，并对第一轮三个问题统一回答“是”。已确认：

1. 重做现有三个顶级页面，允许调整名称、顺序和内容归属；相关二级页面按需要配合调整。
2. 优先解决功能归属和常用操作是否好找，再处理视觉细节。
3. 借鉴 OppoPods 的页面分工、分组和操作方式；保留 Miuix、Material 3 两套界面风格各自的默认组件外观。

第二轮用户统一回答“确认”，进一步确定：

4. 三页职责以第四轮修正为准：耳机页显示当前设备、电量、降噪快捷操作及耳机功能入口；系统页展示状态与诊断入口；设置页集中应用及系统偏好，包括界面风格、明暗模式、连接偏好、超级岛、焦点通知、模块显示时机和关于。第二轮曾将系统配置集中到系统页，第四轮用户明确改为参考 OppoPods，将配置统一放入设置页。
5. 导航顺序保留“耳机 / 系统 / 设置”，应用启动时默认进入耳机页。
6. 耳机首屏压缩插图和设备介绍，优先呈现型号、连接状态、电量和降噪模式；ZT、RS Common V2 等型号配置标识移入设备详情。首页直接提供降噪控制，均衡器、触控、音频设置继续通过列表入口进入。

第三轮用户统一回答“是”，进一步确定：

7. 未连接时，耳机页直接显示附近设备列表和扫描入口，由用户手动启动扫描；权限不足、蓝牙关闭、连接中及失败在同页处理，连接中提供取消入口，连接成功后原地显示耳机控制。
8. 系统未就绪时仍允许修改和保存系统呈现偏好，明确偏好保存与系统实际生效是不同状态。结合第四轮修正，未就绪原因与诊断入口位于系统页，偏好设置位于设置页；仅暂未就绪不会导致适用于该平台的设置消失。
9. 普通页面仅呈现必要的等待、成功或失败反馈；等待时保留设备已确认的选中状态，失败时就近显示原因。详细请求编号、分步确认及已有历史记录集中到诊断页。

第四轮用户确认 Q10、Q11，并修正 Q12 及此前的配置归属：

10. 已连接时，耳机页右上角改为菜单，提供“断开控制连接”；断开后回到附近设备列表。此操作结束 OpenRose 的控制连接，不请求系统断开蓝牙音频或取消配对。
11. 诊断固定入口统一放在系统页，相关错误旁提供“查看详情”；手机与宽屏采用相同的信息层级。
12. 系统页参考 OppoPods 展示状态，所有应用及系统配置项统一放在设置页。Q12 原先针对系统页配置列表的布局提议未获确认。
13. 平台相关的设置项与内容只在对应平台显示。第五轮确认了各平台具体状态页内容，见上方可见性表。

第五轮用户对 Q13、Q14 统一回答“确认”：

14. “全部设置”指应用偏好和系统集成配置，降噪、均衡器、触控等耳机控制仍通过耳机页操作。
15. 各平台保留系统页，仅展示本平台状态：普通 Android 显示蓝牙权限、蓝牙状态及诊断入口；HyperOS 另加模块与系统集成状态；Windows / Linux 显示本平台蓝牙与运行状态及诊断入口。超级岛、焦点通知、融合设备中心等内容只在适用的 HyperOS 平台显示。

## 参考事实

- 当前 OpenRose 的三个顶级页面为“我的耳机 / 系统集成 / 设置”，导航标签为“耳机 / 系统 / 设置”，初始页为耳机页。
- 访谈时的代码中，超级岛模式和模块显示时机位于设置页，焦点通知位于系统集成页；这与 `docs/specs/ui-default-styles.md` 将这些设置集中在系统集成页的划分不同。本次已确认新的归属：应用与系统偏好集中设置页。
- OppoPods 采用项目已有固定参考提交 `c201e251e68b59d46b6bc2758146b2c7f13ca2a1`。该提交的三标签依次为“模块 / 耳机 / 设置”：模块页呈现模块、蓝牙和系统状态；耳机页在设备选择与当前耳机详情之间切换；设置页承载配置项，关于是其二级入口。事实来自本地 Git 对象中的固定提交，未使用另一工作区 HEAD 代替。
- OppoPods 页面与交互可作为参考；ROSE 的可用控制仍由 OpenRose 已有型号能力与设备状态决定。

## 已有约束

继续沿用 [ADR 0001](../../../docs/adr/0001-preserve-control-session-on-style-switch.md)、[ADR 0002](../../../docs/adr/0002-shared-kotlin-core-and-platform-adapters.md) 和 [ADR 0003](../../../docs/adr/0003-official-island-and-headset-notifications.md) 中的会话、平台及系统呈现约束。第一轮未提出修改这些约束。

本轮未提出改变的现有行为继续作为基线：手机底栏、宽屏侧栏和首页双列仍按既有断点工作；关于仍是设置页底部的信息行。系统触发时机目前仅有已开放的“连接时”，不增加新的型号能力、框架激活功能或桌面蓝牙功能。

选中值仍来自设备已确认状态，待确认期间按既有规则禁用设备控件；错误就近显示，详细请求编号、分步确认和已有操作记录集中诊断页。切换界面风格保留控制会话、导航、滚动位置和草稿。

本次是可逆的页面组织与呈现调整，未改变已有 ADR 的会话所有权、技术路线及系统呈现语义，因此不新增 ADR。已在 `GLOSSARY.md` 记录确认采用的“控制连接”术语。
