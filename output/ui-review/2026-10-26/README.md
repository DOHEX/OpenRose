# OpenRose 界面设计审阅 · 第一轮

使用内置图像生成工具制作，尚未修改应用界面。可通过同目录 `index.html` 浏览全部设计稿，点击放大并用左右方向键切换。

## 设计方向

将目前单页长滚动的控制与设置拆为「耳机 / 系统 / 设置」三个主入口及功能详情页。浅色稿使用灰白背景、白色分组卡片、蓝色选中态与大留白，贴近 Miuix；桌面稿探索同一结构的深色外观与双列布局。

Miuix / Material 3 仍是两套独立组件风格，与跟随系统 / 浅色 / 深色显示模式分别设置。本轮主要审阅整体布局和视觉方向，Material 3 在设置稿中提供选择入口与缩略示意。

## 数据与能力约束

- 图中的 i7、固件条件下可见的控制、电量及状态仅为审阅示例；耳机外形为概念示意，不是实物还原。实现时所有控制项由型号配置及实际固件能力决定。
- 充电盒未知电量保持「未知」，不填充虚构百分比。诊断与详情中的未知、未提供、读取中、读取失败必须保留各自语义。
- 控件选中态表示设备已确认的状态。提交、写入和设备确认分别呈现；自定义 EQ 草稿不等于设备当前曲线，模式与曲线需要分别确认。
- 降噪和通透档位按当前模式显示；本轮图中使用 1 / 3 / 5 离散档位，不改成连续强度值。i5 与 i7 的模式和固件能力差异在实现时保留。
- 触控页面修改映射，不执行对应动作；佩戴检测功能开关不表示当前佩戴状态。音频偏好不等于系统已协商的编码；听力保护阈值为型号标签。
- 系统集成未就绪时，偏好保存不表示已经产生系统展示。超级岛模式、焦点通知和连接触发分别设置；目前不开放佩戴、摘下或入盒触发。
- 强制 BLE 只影响下次连接。切换页面、界面风格或外观不重建控制会话，也不重放设置。
- 桌面稿为布局预览，当前 Linux / Windows 蓝牙接入尚未完成，不表示桌面设备控制已可用。

## 审阅建议

先看 01 的整体风格与首页层次，再看 03—06 的控制密度、07—09 的设置层次，最后看 10 的桌面布局。可按编号反馈希望调整的地方。

本轮是关键页面的静态概念稿；连接中、权限缺失、扫描失败及各型号条件分支未逐一展开。确认方向后，再补齐交互状态和组件细节。
