# 清理代码注释

代码不带注释。代码看不出的信息各有归处：决策写进 `docs/adr/`，变通实现登记为 GitHub issue，术语写进 `GLOSSARY.md`。detekt 规则 `openrose:NoComments`（`tools/detekt-rules`）逐文件检查注释数，`config/detekt/comment-budget.txt` 记录遗留注释的**预算**，格式为每行 `<注释数> <相对路径>`。预算只降不升：文件的注释数超过预算时报错，低于预算时也报错，要求把预算降到实际值；降到 0 时删掉该行。

用户给出范围（目录、模块或文件）时只处理该范围；没有给出时，处理预算文件中的全部条目。

## 1. 逐条归类

先读 `GLOSSARY.md` 和 `docs/adr/` 中与该范围相关的 ADR。之后对范围内 `*.kt`、`*.kts` 的每条注释（KDoc、`/* */`、`//`，含行尾注释）判定一类：

- **同义反复**：复述代码已经表达的内容，如名称、签名或显而易见的行为。
- **过时**：指向已不存在或已不一致的代码、行为、名称或 issue，包括被注释掉的代码。已有 ADR 写全了的决策，也归入这一类。
- **借口**：为临时、绕路或 hack 实现开脱，如“暂时”“绕过”“先这样”“等 X 修好”，或用吞掉异常、sleep、重试来掩盖竞态。
- **决策记录**：代码无法还原的重要决定，如逆向得到的协议事实与字节布局、固件怪癖、实机证据、平台限制，或否决某方案的理由。

**完成标准**：范围内每条注释都有归类，并能指出依据。

## 2. 按类处理

- 同义反复、过时：删除。
- 借口：删除，并按 [docs/agents/issue-tracker.md](../../../docs/agents/issue-tracker.md) 提 issue。相关的 hack 合成一个 issue，正文写明涉及的文件与符号、原注释原文、hack 的具体所在和正确做法，加 `needs-triage` 标签。提交前先列出拟提的 issue，经用户确认后再提。
- 决策记录：删除，把原文的事实迁入 ADR。同一主题已有 ADR 时补充到该 ADR；否则沿用 `docs/adr/` 的格式和编号新建，写明出处的模块与符号。若与已有 ADR 冲突，指出冲突的 ADR 并请用户裁决。

只改注释。代码、字符串字面量（注意其中的 `//` 和 URL）与注解保持原样；删除行尾注释时保留该行代码。

**完成标准**：每条借口都对应一个 issue 编号，每条决策记录都能在某个 ADR 中找到。

## 3. 收紧预算并验证

1. 运行 `./gradlew spotlessApply`。
2. 运行 `./gradlew detekt`。每条 `NoComments` 报告都给出文件的实际注释数：把预算文件中对应的行改成该数，为 0 时删掉该行。
3. 重新运行 `./gradlew detekt`，确认通过。

**完成标准**：`./gradlew detekt` 通过，范围内所有文件都已从预算文件中删除，或预算等于留下的、写明了理由的注释数。

## 4. 报告

报告以下内容：各类的条数与行数、新建或补充的 ADR、提的 issue 编号、预算文件减少的行数与注释数，以及仍保留的注释和保留理由。
