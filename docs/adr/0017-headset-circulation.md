# 耳机流转：HyperOS 设备之间由系统完成，与桌面端之间由 OpenRose 连接接力

用户希望 ROSE 耳机能在音源设备之间流转：小米手机与小米手机之间，以及小米手机与 Linux／Windows 桌面之间。HyperOS 自带的「耳机跨设备切换」面向同一小米账号下的受支持设备。小米电脑管家也为部分耳机实现了跨设备控制，但尚无证据表明普通 Windows 或 Linux 客户端能通过公开接口将实际所连的 i5 发布为手机或手环里的可控耳机。见[手机与电脑管家核对记录](../research/hyperos-desktop-headset-card.md)。HyperOS 设备之间沿用系统流转，OpenRose 负责让系统认出 ROSE 耳机；与桌面端之间由 OpenRose 自建通道，按「让出 → 让出回执 → 接入」完成连接接力。代码以 `circulation` 指耳机流转，与 HyperOS 的 `circulate` 一致，避免与控制方式交接的 `Handoff` 混淆。

## 决策

- **共同前提**：参与流转的每台手机都启用模块并选择模块控制。普通控制期间暂停模块增强功能（[ADR 0011](0011-dual-host-single-control-session.md) 第 5 条），流转也不例外；桌面流转中，手机接入需要主动发起 A2DP 连接，公开 SDK 做不到，`BluetoothA2dp.connect` 要求 `BLUETOOTH_PRIVILEGED`。设计不以多点连接为前提。
- **HyperOS 设备之间**：先与固定参考 OppoPods `c201e25` 完全对齐。小米蓝牙 binder 上的 `isSupportAudioSwitch` 返回 `"1"`，`checkSupport` 与 `getDeviceInfo` 返回合成掩码 `01010607,000000000000000010000000`。MiLink 上的同名方法保持 0：OppoPods `b9313e9` 表明它控制空间音频卡片，与流转无关。两台设备实测流转成功后，逐个撤掉伪造，正式版只保留真正起作用的钩子。此前「不伪造含义不明的掩码」的立场由此推翻，代码注释改写理由。
- **目标设备上的身份识别**：目标设备上耳机尚未连接，没有当前会话。模块宿主据已配对且已识别型号配置的 ROSE 耳机，回答身份类查询（`isMiTWS`、`checkIsMiTWS`、`isSupportAudioSwitch`、`checkSupport`、型号 ID）。电量、降噪等状态类查询仍只来自当前会话，不呈现过期状态。
- **桌面流转只由用户发起**：OpenRose 只在用户发起的耳机流转中让出或接入系统音频连接，其余场景仍不改变音频连接。控制连接按 [ADR 0005](0005-miuix-nav-and-audio-bound-control-lifecycle.md) 随音频连接迁移，不改变控制方式与所有者。
- 本轮覆盖手机与 Linux、手机与 Windows 两组双向流转。先在 Linux 上打通流转，Windows 在蓝牙控制落地后接入。每组都用 i5 验证「接到这台电脑」和「接回手机」：目标设备播放的声音能从耳机听到，OpenRose 也能在该设备上继续控制耳机。两台电脑之间直接流转留到下一阶段。
- 本轮也覆盖这两组设备之间双向的耳机远程控制。完成流转配对后，在手机快捷面板或电脑托盘可看到 i5 当前连接的音源设备、电量和降噪模式。点按模式时，由持有耳机控制连接的设备写入，收到耳机确认后更新两端；音频保持原处。「接到这里」另行发起音频流转。两组都要分别验收手机持有和电脑持有耳机的情形。
- 首版手机与桌面的耳机远程控制同样要求手机启用模块并选择模块控制。普通 Android 模式下只查看远端电量、切换降噪的场景留到第二阶段。
- 优先验证澎湃融合设备中心原生卡片里的远程控制。原型验收时让 Linux 通过 i5 播放，手机与 i5 断开蓝牙。手机原生卡片应显示持有耳机的电脑名称；在原生降噪区点「通透」，电脑收到耳机确认，播放继续。手环的融合设备中心单独验收能否看到这副 i5 并调节降噪。原生降噪场景验证通过后，再评估是否在手机卡片里增加独立的游戏模式开关。Windows／Linux 上的 OpenRose 基础互联可独立交付。
- 兼容型号由 OpenRose 选择，首版沿用 Xiaomi Buds 3 Pro（`01010607`）。其他型号先在开发测试中比较。若某个系统版本需要特定型号才能正常工作，由 OpenRose 自动匹配；只有实测表明不同选项存在用户可感知的取舍时，再考虑提供手动选择。
- **连接接力**：用户在要接入的音源设备上发起「接到这里」：
  1. 它向所有流转配对过的音源设备发出让出请求，由持有耳机的那台让出（手机由模块断开 A2DP 与 HFP，Linux 调 `Device1.Disconnect`）。
  2. 持有方回执让出后，发起方才接入。
  3. 手机正在通话，或 Windows／Linux 能确认这副耳机的麦克风正在被使用时，持有方拒绝让出，发起方显示具体原因。电脑只通过耳机播放音乐或视频时照常让出。
  4. 所有已配对对端都在线且均回复「未持有」时，发起方直接尝试接入。联系不上任何对端时，说明情况后仍尝试直接接入。收到明确的占用拒绝时保留原连接。
  5. 接入超时或失败时只在发起方显示失败与原因，不自动退回原音源设备。
- 电脑接入耳机后保留用户的系统默认输出。如果默认输出仍是其他设备，托盘同时显示耳机已连接和当前输出设备，并提供打开系统声音设置的入口。流转验收时分别确认音频连接、实际出声和耳机控制。
- 目标设备已接入耳机音频时，卡片显示本机为音源设备。耳机控制恢复失败时提供「恢复耳机控制」，播放继续。
- **入口**由目标音源设备提供。「我的耳机」、桌面托盘面板和手机快捷面板共用耳机卡片的音源判断与操作。能按蓝牙标识确认远端持有这副耳机时，显示音源名称、电量和可用降噪模式。「改连这台电脑」或「改连这部手机」请求原音源让出耳机。暂时无法确认音源时，只说明本机的连接情况，并允许手动尝试本机接入。流转反馈留在发起操作的耳机卡片上。两台 HyperOS 设备之间仍从融合设备中心发起流转。
- **通道与流转配对**：同一局域网内直连，经 mDNS 发现，用 TLS 并固定对端证书。电脑显示二维码与 6 位配对码，手机在 OpenRose「设置」中扫码或输入；每条消息都要认证，任一端删除流转配对后，拒绝对方的一切请求。手机端端点在模块宿主（`com.android.bluetooth`）内：单独的线程，限制报文长度，只接受流转配对过的对端。

## 考虑过的方案

- **桌面端实现 MiLink**：协议闭源，设备互信依赖小米账号，逆向成本与稳定性都不可接受。
- **KDE Connect 插件**：kdeconnect-android 的插件在编译期经 KSP 类索引收集，不能加载外部插件，只能合入上游或发行分叉；KDE Connect 进程也碰不到 A2DP，还要新增一个调用模块宿主的角色。桌面端 kdeconnect 不安装头文件，`libkdeconnectcore` 的 soname 随版本变化，插件须用 C++／Qt 针对每个版本重新编译，且只覆盖 kdeconnectd。它能省掉的只有发现、配对与 TLS，而两端都是 OpenRose，这部分可以共用 Kotlin 实现。以后可以为 KDE Connect 的「运行命令」提供一个命令行入口，作为手机触发拉取的附加方式。
- **多点连接加暂停另一台**：效果取决于固件在两台音源之间如何仲裁，协议研究里没有切换音源的命令，仲裁行为未知；i5 开启多点后不能用 LDAC。
- **通道端点放在应用进程**：应用没在运行时，桌面无法请求手机让出，局域网消息也唤不起应用，与模块自治相违。
- **在钩子进程按设备名识别耳机**（HyperRose 的做法）：会在 core 之外另做一套型号识别，而名称不足以确定型号配置。

## 后果

- 系统蓝牙进程多了一个网络端点，这里的缺陷会影响整个系统蓝牙。2026-11-21 在小米 14（HyperOS 4.0.0.27，Android 17）核对到蓝牙宿主已获授 `INTERNET`。该机的局域网发现、收发和锁屏后的可达性仍待实测。
- 首版手机与桌面之间的耳机流转和远程控制要求两端处于可互访的局域网。电脑接网线、手机连 Wi-Fi，只要两端能互访就属于支持场景。仅在蓝牙范围内、两端网络彼此隔离的场景留到后续。
- Windows 接入时，需要经 `KSPROPSETID_BtAudio` 的 `KSPROPERTY_ONESHOT_RECONNECT`／`KSPROPERTY_ONESHOT_DISCONNECT` 连接和断开音频。
- 尚待实机确认：HyperOS 流转由哪些钩子打开；ROSE 耳机在关闭多点时能否完成流转；让出之后另一台能否接入。首验用小米 14 加另一台 HyperOS 设备、维护者的 CachyOS（niri）桌面与 i5。
- 另有一个需要区分的双机场景：关闭耳机多点，由手机 A 保持播放，在手机 B 的融合设备中心切换降噪。验证时需确认 B 未直接连接耳机、A 的音频仍在耳机上播放，并核对 A 收到操作和耳机回报的新模式。小米分别公开了[融合设备中心的操控能力](https://os.mi.com/continuity/abilities/ab0000)、[耳机卡片的降噪选项](https://www.mi.com/tw/support/faq/details/KA-703964/)和[耳机跨设备切换](https://os.mi.com/continuity/abilities/ab0005)，未说明这条双机降噪请求的传递路径。
- 2026-11-21 在小米 14 与 Linux 桌面间切换 i5，实测电脑独占音频时未置顶的耳机卡片消失，置顶卡片只能打开离线提示。该版小米系统包有远程耳机模式控制路径。如何让系统卡片展示经 OpenRose 配对的电脑及其耳机，仍待验证。见[真机记录](../research/hyperos-desktop-headset-card.md)。
