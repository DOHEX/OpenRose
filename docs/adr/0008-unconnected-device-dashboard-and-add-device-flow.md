# 未连接设备看板重构与添加耳机独立流程

## 背景

在 ADR 0005 与 ADR 0006 确立了导航与主页面 Pager 架构之后，未连接状态下的“我的耳机”主页仍残留早期的扁平原型设计：

1. **信息架构混杂**：主页在已有配对设备（如 `ROSE EARFREE i5`）的情况下，直接在下方内嵌了 `NearbyDevicesPanel`（扫描新设备按钮、附近设备列表），将日常高频的“就绪重连”与低频的“搜索配对”杂糅在同一屏内。这不仅导致页面纵向布局破碎、底部留白巨大，也让用户难以聚焦当前主力耳机。
2. **顶栏规范倒退与操作矛盾**：代码在未连接时强制使用居中的 `SmallTopAppBar`，以迁就内容区硬编码的大标题“连接你的 ROSE 耳机”，破坏了三大主页间一致的 Miuix / Material 折叠大标题体验；同时在未连接时顶栏反而隐藏了 `+` 添加按钮，与添加硬件的心智相悖。
3. **硬件表现力与连接心智缺失**：已有配对设备在未连接时仅展示一个 24dp 简陋小图标，未复用已有的 `EarbudsArtwork` 矢量组件；缺乏“耳机开盖自动连接”的心智提示，当耳机处于离线盒内时，单薄的“连接”按钮点击后超时报错，缺乏阶段反馈与系统蓝牙跳转指引。
4. **配对流程割裂**：虽然定义了 `Route.AddDevice`（`AddDevicePage`），但首页并未将其作为主要配对路径，造成两处维护扫描界面的冗余。

## 架构决策

### 1. 架构解耦：未连接设备看板与添加流程彻底分离

- **未连接设备看板（主页未连接态）**：聚焦于已配对设备的连接状态管理，提供清晰的开盖自动连接心智、大卡片视觉锚点、手动重连与多设备切换能力。主页彻底剥离 `NearbyDevicesPanel` 扫描逻辑与列表。
- **添加耳机流程（`Route.AddDevice` 全屏页）**：作为独立全屏二级路由，隐藏底部导航栏，独占承载新设备搜索、信号雷达、权限引导与首次配对绑定交互。

### 2. 顶栏规范对齐与大标题统一

- 废除未连接时强制降级为 `SmallTopAppBar` 的分支，未连接与已连接状态完全统一使用标准 Miuix / Material 折叠大标题（“我的耳机”）。
- 移除内容区硬编码的双重标题文字。
- 顶栏右上角在未连接时常驻 `+` 动作按钮，点击直接进入 `Route.AddDevice`；已连接时则展示功能菜单。

### 3. 未连接设备看板设计规范

- **首选设备大卡片（已有配对设备）**：
  - **视觉锚点**：卡片上方使用 `EarbudsArtwork` 矢量组件展示耳机精致外观。
  - **型号与状态**：清晰标注设备名称、型号配置胶囊标签（如 `ZT` / `RS Common V2`），并明确呈现“未连接 · 耳机开盖后将自动连接”的状态提示。
  - **操作与兜底**：卡片内包含显眼的“连接”主按钮；点击后提供连接中加载过渡动画；若连接超时或失败，提供“重试”与“前往系统蓝牙设置”辅助跳转。
- **多设备切换**：当系统内存在多副已配对 ROSE 耳机时，大卡片下方以简洁列表呈现其余设备，支持一键切换首选设备并发起连接。
- **底部辅助入口**：在设备列表末尾提供次级“配对新耳机”单元格，与顶栏 `+` 形成双通道可达。
- **首访空态（0 已配对设备）**：展示居中 `EarbudsArtwork` 引导图、“添加你的 ROSE 耳机”标题与开盖靠近指引，提供全宽“搜索并添加耳机”主按钮及系统蓝牙跳转入口。

### 4. 添加耳机独立页的自动化生命周期

- `AddDevicePage` 采用进入页面自动检查蓝牙并触发扫描（`onStartScan`）、退出页面（返回手势或点击返回）时自动停止扫描（`onStopScan`）的生命周期绑定，杜绝后台无谓耗电。
- 当用户在设备列表中点击并成功建立控制连接且进入就绪状态（`ConnectionPhase.READY`）时，自动回退至根主页，主页无缝展示主控制看板（降噪、均衡器、电量等）。

## 验证与影响

1. **视觉与交互保真**：在真机与桌面端验证大标题折叠动效、`EarbudsArtwork` 未连接呈现、多设备切换与开盖自连指引。
2. **路由与生命周期**：验证从顶栏 `+` 或底部进入 `Route.AddDevice` 时的自动起扫、手势返回时的自动停扫，以及连接就绪后的自动回退流转。
3. **测试兼容性**：更新受影响的 UI 测试断言，确保 Miuix 与 Material 3 双风格均保持完备测试覆盖。
