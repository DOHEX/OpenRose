# 沿用 RoseLink 的固件比较、广播前缀与名称识别规则

型号能力按固件门控，型号识别依赖广播的厂商数据和设备名称。这些规则若与官方 App RoseLink 不一致，同一副耳机在 OpenRose 中可能被识别成另一个型号配置，或开放 RoseLink 并未开放的功能。因此固件比较与广播识别照搬 RoseLink 的做法；只有在没有广播可用时，才按名称识别，并采用保守规则。

## 决策

- **固件比较**：RoseLink 把三个完整的无符号固件字节按十进制文本拼接，再作为整数比较。`firmwareComparisonInteger` 只接受恰好三段、每段 0–255 的固件，例如 `2.1.3` 比较值为 213。
- **固件未知时门限未定**：`firmwareAtLeast` 在固件未读或格式不符时返回 null，此时门限未定，门限之后的能力为未知，不按最低版本推定。
- **提示音关闭档**：`promptVolumeLevels(firmware, offSince)` 在固件达到 `offSince` 时加入关闭档 0（0..5），未达到时为 1..5；读到固件之前为空，表示未知。
- **广播前缀**：
  - `ModelIdentification.normalizedHex` 先拼接排好序的全部 company ID（每个按小端两字节），再拼接按同一顺序排列的全部载荷。
  - `identify` 与 RoseLink 一样，依次用规范化数据的前 12、8、6 个十六进制字符查表，因此注册的最长前缀胜出（`ROSELINK_PREFIX_LENGTHS`）。`ModelSpec` 要求前缀为这三种长度之一且为小写十六进制，前缀表不允许两个型号配置重复。
- **RS 系列读数**：`rsReadings` 按硬件电量布局给出电量槽位：只有耳塞的型号没有充电盒槽位，单体型号只有充电盒槽位。其他字段须有该型号的证据才列为可读。
- **名称识别**（`ModelProfile.match`）：
  - 只凭名称的证据，用于没有广播数据的已配对设备与音频连接。
  - 名称须像 ROSE 设备（以 ROSE 前缀开头或含品牌词）。随后由型号号决定；名称里没有型号号时，才由品牌词决定。
  - 明确的代际（MK2、Swift 2）优先于不带代际的零售品牌名。
  - `nameTokens` 按整词切分，包括多词品牌和不加分隔的写法（如 EarFeeli5）。“Swift 20” 不能回退匹配到 “Swift” 或 “Swift 2”。

## 后果

固件门限、广播前缀与 RoseLink 保持一致，未读到固件的设备在读到固件之前不开放受门控的能力。按名称识别只是退路：名称有歧义时宁可不识别，也不猜测型号。
