# i7 十段 EQ 与固件受限音频设置

日期：2026-10-19（Asia/Shanghai）。范围：[十段自定义 EQ #13](https://github.com/DOHEX/OpenRose/issues/13)、[增益、保护与提示音 #14](https://github.com/DOHEX/OpenRose/issues/14)。实现基线为 `21c6869`。设备暂不可用，用户要求继续实现与离线验证；i7 的全部设置与接收样本仍待硬件验收。

## 曲线与分阶段确认

- i7 提供十个整数增益，顺序标签为 20 / 100 / 300 / 500 / 1k / 2k / 3k / 5k / 8k / 15k，范围 −6～6。这是恢复的界面频段标签，不是实测滤波器参数。
- 应用曲线经同一队列先发送自定义模式 `2A04`，再发送 `3E` 和十个符号位加绝对值编码的整数；两帧使用不同的连续序号。参数和整个计划容量须在首次写入前检查。
- 模式与曲线分别读取，各自建立新回读基线。仅第一帧底层写入完成不能称为自定义模式已经生效；新模式回读也不能证明曲线已应用。全部有效回读匹配后才整体确认。
- i7 自定义模式为 4；`5 + slot` 是独立的 `custom_slot` 状态。保留原始格式及槽位，不能把后者自动当成模式 4 的成功回读。
- 草稿与设备已确认状态分别显示；复制设备曲线、从零创建及编辑草稿均为显式操作。风格切换保持草稿和在途请求。
- 部分写入、部分确认和整项确认分开记录；失败、超时或断开后保留已观察的操作事实，不自动回滚或重放。

## 固件能力

比较域与 EAP 一致：验证前三个完整无符号固件字节后，将其十进制文本无分隔拼接为整数；不使用显示标签、半字节或语义化版本比较。未知固件不能满足门槛。

- 增益和保护需整数 ≥213。增益线值 0 / 1 / 2 是低 / 中 / 高三个档位，没有具体增益 dB 对照证据。
- 保护线值 0 为关闭，1～6 对应恢复的 75 / 80 / 85 / 90 / 95 / 100 dB 阈值标签；标签不代表本项目已测量声压或验证保护效果。
- i7 普通提示音 1～5 档不受 304 门槛整体限制，固件未知时也可提供；只有关闭值 0 要求整数 ≥304。i5 仍为界面 1～5 对应线上 0～4，不引入关闭语义。

独立来源与协议向量见 [protocols.md](../protocols.md)。本阶段没有提示音语言或 OTA 入口。

## 验证结果

- 新增 6 项协议测试，涵盖能力门槛、参数与输入快照、符号绝对值编码、两写两读和混合序号、custom / custom_slot 及数值设置的合成回读；预期 TX 使用独立提取或明确推导的字面值。既有协议测试继续执行，并更新 i7 基础提示音的阶段能力预期。
- 新增 13 项公开会话测试，覆盖完整流程、16 字节容量预检、首 / 次写失败、部分发送、早到曲线不能代替后续查询回读、未知 / 缺失 / 已知不同、确认后变未知、部分超时 / 断开事实、风格切换 / FIFO 及 213 / 304 / 未知固件的公开设置结果。保留已有能力和 custom tracer 的红绿记录，接续实现并扩展边界验证。
- JVM 与 Android host JVM 各执行 133 项测试，零失败；`--offline check offlineCheck :androidApp:assembleDebug :desktopApp:createDistributable` 全部通过，共 122 项任务。Android host JVM 不代表真实手机，桌面分发构建不代表 Windows 实际启动。
- 独立 `.scratch/advanced-ui-smoke.sh` 在真实 `OpenRoseApp` 中实际点击创建零草稿、修改、应用；写入 1/2 时切 Miuix → Material 3，模式确认后切回 Miuix，草稿、会话与发送次数保持不变。两个回读分别确认后才整项成功。
- 同一 i7 公开会话用合成固件通知驱动未知 / 212 / 213 / 303 / 304 能力入口，并实际执行增益、保护与提示音关闭设置。第二次曲线回读未知时超时结束链路，操作保留 2/2 发送和仅模式已确认，未自动重放。
- UI 发送量为 4 项初始化 + 4 项首次曲线写 / 读 + 2 项增益 + 2 项保护 + 2 项提示音 + 4 项第二次曲线写 / 读 = 18。截图、语义树和 TX 保存在任务本地 `.scratch/advanced-ui-smoke/`。所有 i7 RX 均为明确标注的合成数据，不能代替真实曲线、档位效果及回读验收。

## 独立双轴审查

固定基线 `21c6869`，两个未参与实现的 Luna max 代理分别检查规范和规格，包含新增文件。

- **Standards**：未发现待处理的可执行问题。会话所有权、协议多阶段操作、草稿与真实状态隔离、型号 / 平台边界符合已接受 ADR。
- **Spec**：发现并修复一项 P2：i7 固件未知或低于 304 时，关闭提示音值 0 应返回能力不支持（UNSUPPORTED），不能与越界参数混为 INVALID_ARGUMENT。公开会话断言先复现旧行为失败，再修复并同步阶段测试；负数、6、错误类型及 i5 的零值仍为 INVALID_ARGUMENT。原审查者定向复核后确认解决，没有新增问题。修复后重跑全套 133 项 / 两运行环境及构建，结果均通过。
