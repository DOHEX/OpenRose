# 首版 spec #1：实现与验收剩余项

状态基线：`d19730c` 后的原生系统整合（2026-10-21）；对应本记录所在提交。这是 #1 的 Android 首版追踪表，不是完成报告。它按 `docs/verification/` 中已记录的实现与离线证据，以及只读 issue 快照 `.scratch/issues-current.json` 汇总。快照内 #1–#32 均为 `OPEN`、`ready-for-agent`；票保持打开不代表实现完全缺失，已实现也不代表真实验收通过。

官方提示、多目标认证桥接、原生耳机和 MiLink 入口已有生产代码，细节及证据边界见 [原生整合记录](system-native.md)。原生能力 mask、MiLink 列表的未知盒充电语义和 OS3/4 目标组件样本仍缺，不能宣布全部实现完成。i5 / 小米 14 当前暂不可用，i7 和 HyperOS 3 验收环境也未有证据；不重复询问设备，不以合成设备替代。

## 最低完成判据

1. **实现**：#1 的 Android 范围有可用生产路径；OS4 官方路径不再恒定 `UNAVAILABLE`，OS3 目标组件有证据化适配，融合设备中心存在真实代码入口。系统模块、通知、岛、融合卡片和应用均使用同一权威 `ControlSession`，没有空 Hook、演示值或第二条发送队列冒充成功。
2. **离线验证**：对应公开会话行为和独立协议向量通过，构建 / lint 证据属于所记录基线。所有模拟 RX、平台事实、通知 probe UID 和跳过场景标注清楚。离线结果只能证明对应的代码边界。
3. **真实 Android 首版验收**：最少覆盖 i5 + 小米 14 HyperOS 4 首验、i7 + HyperOS 4 系统入口、HyperOS 3 的 i5 与 i7 两个型号、真实 i7 BLE / 专用 SPP 适用链路及已实现控制回读；并在目标 OS 上完成官方 / 模块呈现、状态通知、六组合、融合设备中心和断连撤销闭环。按 issue #28–#30 分型号、固件、ROM、组件、框架和操作留下记录。缺任何必需设备环境或结果时，只能报告实现完成 / 对应组合待验，不能关闭 #1。
4. **桌面阶段**：#31 Linux、#32 Windows 为 Android 首版后独立工作；它们未完成不阻塞 Android 首版，Linux 的结果也不能代表 Windows。

## 必须继续保持 OPEN 的外部验收

当前没有可用 i5 / i7 实机及 HyperOS 3 / 4 目标手机证据。对应剩余实测包括：#3 i5 读取与断开、#5/#7/#9/#11 i5 控制回读、#16 Android 真蓝牙恢复、#17 i5 Android 在途风格切换、#18 有效框架正向跨进程桥接、#19–#27 目标 OS 系统入口（按对应 OS / 型号）、#28 i7 全部已实现控制与传输、#29 i7 OS4、#30 OS3 上 i5 与 i7。用户已明确暂时无法提供设备；继续实现和离线验证，不反复询问设备可用性，也不把现有 API 26 emulator 或任何合成输入升级为实机通过。
