# i5 / i7 预设 EQ 与游戏模式实现、离线验证

日期：2026-10-19（Asia/Shanghai）。范围：[i5 预设 EQ 与游戏模式 #7](https://github.com/DOHEX/OpenRose/issues/7)、[i7 预设 EQ、EAP 与游戏模式 #8](https://github.com/DOHEX/OpenRose/issues/8)。实现基线为 `f881b62`。用户当前无法提供实机，继续实现与离线验证；真实设置、听音效果和持久化均未验证。

## 型号能力与确认

- i5 的四种预设为 POP / HIFI / ROCK / LIGHT，不开放自定义 EQ。i7 提供同四种基础预设，EAP 是 EQ 的一种选择，由已知固件整数是否达到 152 决定。
- i7 固件比较使用接收器前三个完整无符号字节的十进制文本拼接，保持研究中的比较域。例如 `[1,5,2]` 为 152、`[0,15,1]` 为 151；不按半字节、语义化版本或应用版本比较。未知固件不能被视为满足门槛。
- 两型号的游戏开关线上极性相反，i7 HIFI / POP 的发送值与双字节回读映射也有区别；共享界面只使用规范化语义。协议和标签来源见 [protocols.md](../protocols.md)。
- 所有请求经公开 `ControlSession.set` 执行能力与参数检查，并使用现有单一会话、串行队列及独立回读确认。提交或底层写入完成均不能直接改写已确认的设备状态。
- 超时、断开、设备回读不同与不支持分别保留结果；超时结束旧链路，重新连接不重放设置。切换界面风格不重建会话或重发请求。

## 验证结果

- 新增 10 项独立协议测试，覆盖全部预设、游戏极性、不同 EQ 回读布局、非法参数、有效固件 parts、EAP 门槛和混合命令序号。预期 TX 为独立 APK 提取或明确标注的独立推导字面值，不通过产品构造器生成。
- 新增 10 项公开会话测试，覆盖全部允许选项、已写未确认、固件未知 / 151 / 152 / 完整字节比较、能力随固件回包更新、非法请求零发送、排队请求执行前复查能力、风格切换及超时清理。原有会话断连、迟到回包与重新连接测试继续执行。
- JVM 与 Android host JVM 各执行 85 项测试，均为零失败；Android host JVM 不等于手机设备测试。`check offlineCheck :androidApp:assembleDebug :desktopApp:createDistributable` 通过，共 122 项任务；额外的 `--offline offlineCheck` 通过。
- 独立 `.scratch/eq-ui-smoke.sh` 通过，主代理重新执行后结果相同。它在传输边界重放 i5 13 项已有 Linux 读取样本，实际点击 POP，写入后切 Miuix → Material 3，保持旧 HIFI 选择、会话和发送次数；合成读回后才确认 POP。游戏未知时开启 / 关闭均不选中，点击开启后由合成回读确认。总发送量为 13 项初始化 + 2 项设置 + 2 项确认读取 = 17。
- 同一 i7 公开会话接收合成固件通知：未知和 151 无 EAP 可执行入口，152 出现入口；两型号使用各自有证据的中文标签。截图、语义树及 TX 记录位于任务本地 `.scratch/eq-ui-smoke/`。合成回复仅用于离线边界验证，不代表 Bluetooth 或硬件测试。

## 独立双轴审查

以 `f881b62` 为固定基线，两个未参与实现的审查分别核对规范和规格，包含新增文件。

- **Standards**：未发现可执行问题。平台拥有会话和队列，固件与型号判断留在共享核心，两套界面消费同一状态；历史请求不会套用当前会话的型号标签。
- **Spec**：未发现可执行问题。独立研究支持预设、游戏极性、HIFI / POP 回读差异和固件整数门槛；`FA0E` 清楚标注为根据已有 FA 查询机制推导的客户端补读，设备接纳仍待验证。实现和文档没有将离线结果扩大为硬件或持久化验收。
