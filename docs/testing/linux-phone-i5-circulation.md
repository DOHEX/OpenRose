# 小米 14 与 Linux 的 i5 流转和远程降噪

2026-11-21 使用关闭多点的 ROSE EarFree i5、小米 14（HyperOS 4.0.0.27、Android 17、模块控制）和 CachyOS 桌面（BlueZ 5.88、PipeWire、niri）。手机与电脑在无线局域网内完成六位码配对。桌面入站 TCP 21871 对该手机开放，手机保留原有 VPN 设置。以下操作使用应用的快捷面板、未连接看板或桌面托盘。

| 场景 | 观察 |
| --- | --- |
| 手机播放，Linux 托盘调通透 | 关闭桌面主窗口，将手机 OpenRose 主应用强停，手机熄屏。Linux 未与 i5 建立蓝牙连接。托盘显示音源 Xiaomi 14、左右耳 87% 和 89%、盒电量未知。选择通透后，原先勾选的抗风噪变为通透。手机测试播放的 AudioTrack 记录到 A2DP 输出，播放帧数持续增长，佩戴者听到手机的三音提示。 |
| 从托盘接到电脑 | 手机仍熄屏，点托盘面板「接到这台电脑」。手机让出后 Linux 的经典蓝牙接入，Android 蓝牙记录确认 i5 的经典和 LE 链路均已断开。原模拟输出保持默认，托盘显示当前输出。向 i5 的 PipeWire 输出定向播放时，该输出为 RUNNING，佩戴者听到电脑的双音提示。 |
| 仅重试耳机控制 | 本次接入后音频先就绪，托盘提示「耳机已接入，控制未连接」。点「重试耳机控制」后，Linux 读到左耳 86%、右耳 88%、盒电量未知及通透，原默认输出不变。手机快捷面板同时恢复电脑名称和读数。 |
| Linux 播放，手机快捷面板调通透 | 先在电脑确认抗风噪，手机面板显示相同模式。手机点「通透」后 Linux 托盘显示设备确认的通透。点按前后 i5 的 PipeWire 输出均为 RUNNING。 |
| 麦克风占用时拒绝流转 | Linux 把 i5 切到免提配置，指定 i5 输入进行采集并丢弃采样。手机点「接回手机」后显示「耳机麦克风正在使用，无法让出」，i5 的采集仍为 RUNNING，Linux 经典蓝牙保持连接。随后停止采集并恢复原 A2DP 配置。 |
| 从未连接看板接回手机 | 桌面修正多地址广播后运行 `5cb2c40`，手机运行包含模块所有者线程修正的 `a408b53`。点「接回手机」后 Linux 的经典蓝牙和 LE 均已断开。手机的两条链路重新连接，读到左耳 84%、右耳 86%、盒电量未知，降噪随后经手机确认恢复为原先的抗风噪。手机 AudioTrack 报告 A2DP 路由，佩戴者再次确认听到三音提示。 |

本表前四项使用桌面 `eb6a4a3` 和包含局域网路由修正的 Android 开发版。融合设备中心的两项结果分别见[手机原生卡片](hyperos-phone-i5-card.md)和[手环原生卡片](hyperos-band9-i5-card.md)。Linux 本机控制的蓝牙回包见[托盘实测](linux-i5-tray.md)。
