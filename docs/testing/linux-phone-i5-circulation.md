# 小米 14 与 Linux 的 i5 流转和远程降噪

2026-11-21 使用关闭多点的 ROSE EarFree i5、小米 14（HyperOS 4.0.0.27、Android 17、模块控制）和 CachyOS 桌面（BlueZ 5.88、PipeWire、niri）。手机与电脑在无线局域网内完成六位码配对。桌面入站 TCP 21871 对该手机开放，手机保留原有 VPN 设置。以下操作使用应用的快捷面板、未连接看板或桌面托盘。

| 场景 | 观察 |
| --- | --- |
| 手机播放，Linux 托盘调通透 | 关闭桌面主窗口，将手机 OpenRose 主应用强停，手机熄屏。Linux 未与 i5 建立蓝牙连接。托盘显示音源 Xiaomi 14、左右耳 87% 和 89%、盒电量未知。选择通透后，原先勾选的抗风噪变为通透。手机测试播放的 AudioTrack 记录到 A2DP 输出，播放帧数持续增长，佩戴者听到手机的三音提示。 |
| 从托盘接到电脑 | 手机仍熄屏，点托盘面板「接到这台电脑」。手机让出后 Linux 的经典蓝牙接入，Android 蓝牙记录确认 i5 的经典和 LE 链路均已断开。原模拟输出保持默认，托盘显示当前输出。向 i5 的 PipeWire 输出定向播放时，该输出为 RUNNING，佩戴者听到电脑的双音提示。 |
| 仅重试耳机控制 | 本次接入后音频先就绪，托盘提示「耳机已接入，控制未连接」。点「重试耳机控制」后，Linux 读到左耳 86%、右耳 88%、盒电量未知及通透，原默认输出不变。手机快捷面板同时恢复电脑名称和读数。 |
| Linux 播放，手机快捷面板调通透 | 先在电脑确认抗风噪，手机面板显示相同模式。手机点「通透」后 Linux 托盘显示设备确认的通透。点按前后 i5 的 PipeWire 输出均为 RUNNING。 |
| 麦克风占用时拒绝流转 | Linux 把 i5 切到免提配置，指定 i5 输入进行采集并丢弃采样。手机点「接回手机」后显示「耳机麦克风正在使用，无法让出」，i5 的采集仍为 RUNNING，Linux 经典蓝牙保持连接。随后停止采集并恢复原 A2DP 配置。 |
| 从未连接看板接回手机 | 桌面修正多地址广播后运行 `5cb2c40`，手机运行包含模块所有者线程修正的 `a408b53`。点「接回手机」后 Linux 的经典蓝牙和 LE 均已断开。手机的两条链路重新连接，读到左耳 84%、右耳 86%、盒电量未知，降噪随后经手机确认恢复为原先的抗风噪。手机 AudioTrack 报告 A2DP 路由，佩戴者再次确认听到三音提示。 |
| 整机休眠、唤醒与再次流转 | 关闭主窗口并保留 Linux 托盘。systemd 日志记录 11:50:14 进入 suspend、11:51:02 返回，内核成功计数从 0 变为 1。经典音频自动接回；桌面 `9523990` 在等待 GATT 时撤下旧读数，随后提示重试。只重试控制后手机与托盘重新取得耳机确认的读数，手机点通透时 Linux 托盘同步确认。再次点「接回手机」成功，Linux 两条蓝牙链路均已释放，托盘重新读取手机所持耳机的 83%、86% 和通透。系统默认输出保持原模拟输出。 |

本表前四项使用桌面 `eb6a4a3` 和包含局域网路由修正的 Android 开发版。融合设备中心的两项结果分别见[手机原生卡片](hyperos-phone-i5-card.md)和[手环原生卡片](hyperos-band9-i5-card.md)。Linux 本机控制的蓝牙回包见[托盘实测](linux-i5-tray.md)。

## 初始化期间切换降噪的实机计时

2026-11-21，小米 14 通过 OpenRose「接回手机」取得 i5。电脑确认手机持有耳机、当前模式为抗风噪后，通过桌面应用使用的流转接口发起「接到这台电脑」。计时程序在收到首个可调节的降噪模式后立即请求通透，使用单调时钟记录状态，并用 BlueZ 的通知独立核对耳机回包。

| 从发起流转算起 | 本轮观察 |
| --- | --- |
| 1.73 秒 | Linux 已有 A2DP 媒体传输。 |
| 6.01 秒 | 读到抗风噪，初始化仍在进行，桌面提交切换通透。 |
| 6.46 秒 | 耳机回读通透，桌面确认设置成功。 |
| 8.70 秒 | 全部初始化查询结束。 |

这次从模式可调到完整就绪相隔 2.70 秒，从请求通透到耳机确认用时 0.45 秒。BlueZ 记录显示，A2DP 媒体传输出现后又过了 3.64 秒，低功耗蓝牙链路才连上。

另一次流转在约 1.7 秒时接入了电脑音频，但桌面等待 GATT 服务约 15 秒后超时。ADB 显示手机的经典蓝牙已断开，超过一分钟后仍持有 i5 的低功耗蓝牙连接，手机 OpenRose 仍显示已连接。通过手机菜单断开控制连接，再接回手机并重新发起流转后，得到上表结果。结束时已从桌面托盘核对 i5 连在电脑上、模式为抗风噪，系统默认音频输出仍是原模拟输出。

### 缩短电脑端等待后的对照

同日用同一副 i5 和同一台小米 14 对照测试。手机覆盖安装了同包名的调试版，保留原有配对。每轮开始时，电脑通过已配对的手机确认 i5 由手机持有、当前为抗风噪。电脑通过正式流转接口接入，读到当前模式就提交通透，等耳机回读后恢复抗风噪。

| 桌面版本与轮次 | 从发起到音频接入 | 可调降噪 | 耳机确认通透 | 全部初始化完成 |
| --- | ---: | ---: | ---: | ---: |
| 调整前，对照 | 1.93 秒 | 12.33 秒 | 12.82 秒 | 14.98 秒 |
| 调整后，第一次 | 2.23 秒 | 5.60 秒 | 5.73 秒 | 7.13 秒 |
| 调整后，第二次 | 1.86 秒 | 4.16 秒 | 4.38 秒 | 5.64 秒 |

三次的首次 LE 连接请求都收到了 BlueZ 的 `InProgress`。从收到该响应到发送下一次请求，调整前实测 2.008 秒，调整后分别为 0.128 秒和 0.372 秒。随后成功的 LE 连接调用分别耗时 7.91、2.81 和 1.63 秒，因此整次流转耗时也受无线连接波动影响。新版提交通透后，两次分别用 0.13 秒和 0.23 秒获得耳机确认；被动监听的 BlueZ 通知也读到了模式变化。

表中只统计从手机已持有 i5 到电脑接入的完整流转。准备反向接回手机时，观察到 Linux 在让出后重新建立 LE，另一次电脑等待发现手机超时，这两种情况都发生在计时开始前。结束时已恢复电脑持有 i5 和原抗风噪模式。
