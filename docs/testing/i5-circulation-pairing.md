# 小米 14 与 Linux 的流转配对

2026-11-21，小米 14（23127PN0CC，HyperOS OS4.0.0.27.XNCCNXM，Android 17）与 CachyOS 桌面在同一局域网。手机选择模块控制，蓝牙宿主已获系统局域网访问权限。电脑使用集成分支的桌面应用，手机使用基于 `f5652f5`、含本文所述路由修复的调试 APK。

手机设置中的流转配对列表发现了电脑。电脑提供二维码与六位码，本次在手机输入六位码，并核对它与桌面新二维码携带的码一致。手机显示「已配对」。随后从手机设置解除配对，手机报告「已解除配对」，Linux 托盘撤下该手机及其电量和降噪操作。打开手机的扫码入口，用相机扫描桌面新生成的二维码后，用户确认重新配对成功，手机再次列出电脑。Linux 托盘重新读到 Xiaomi 14 所持 i5 的 83%、86% 和未知盒电量，已确认模式为抗风噪。耳机电量、模式回读、实际播放与休眠恢复各自验收。

路由修复前，系统 mDNS 在 Wi-Fi 上发现同一电脑的多条 IPv4／IPv6 服务。手机的系统蓝牙宿主处于 VPN 的 UID 选择范围，选择默认套接字后配对失败。桌面可接受来自手机 shell 的 IPv4 TCP 连接，但桌面 JVM 在当次失败的配对中未观测到相应 TLS 握手。修复后，Android 对每个已解析服务使用 NSD 报告的网络创建套接字，并先尝试同一对端的 IPv4 地址。系统 VPN 设置保持原值，两个设备完成 TLS 连接与配对码校验。
