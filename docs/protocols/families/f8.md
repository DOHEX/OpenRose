# F8 协议族

RoseLink 3.8.0（versionCode 5310，APK SHA-256 `83cdd7e3e7f6e7d61a26dc6a8fab65f183d5a18a66a70f64a17f69d93e58e40b`）中有 6 个耳机配置使用 F8：AGATE、AGATE X、CERAMICS、CERAMICS-X、CERAMICS-X-7034、EXPLORER。本文是整理这一族任何型号时的入口，说明哪些部分全族共用、哪些按型号变化、各自的证据在哪。F8 的所有结论都来自静态分析；没有任何一款 F8 耳机做过实机收发或抓包，设备是否接受这些命令、真实广播与通知字节都未验证。

## 全族共用

6 个配置的构造函数都实例化 `F8Sender`（或其子类）和 `F8Receiver`；EXPLORER 的 Sender 是 `ExplorerSender extends F8Sender`，只覆写 `setNoiseModeNormal`。接收处理器分三组：AGATE、AGATE X、CERAMICS 用 `AgateReceiveHandler`（cid 431），CERAMICS-X 与 CERAMICS-X-7034 用 `CeramicsXReceiveHandler`（cid 429），EXPLORER 用 `ExplorerReceiveHandler`（cid 430，`extends CeramicsXReceiveHandler`，只覆写 `ancDataReceived`）。因此帧格式、命令编码和通知分派属于协议族，型号只决定开放哪些控件、取哪些值、以及回调落到哪个处理器。

## 全族已知的坑

- `getKey` 的首字节是 `02`，不是 `00`；不要规范化（发送分析（`rose_reverse/analysis/agate_commands_findings.md`））。
- F8 帧没有应用层校验和或尾字节，`transform` 是恒等；不要自行追加 CRC（分派表（`rose_reverse/analysis/i7_dispatch/table.tsv:1691`））。
- `LEN` 是 byte4 的单字节还是 byte3–4 的 16 位大端长度，静态无法区分；所有已见 LEN≤3（F8 帧格式（`rose_reverse/analysis/ceramics_f8_protocol.md`））。
- 接收端对 `27` 和 `28` 没有分支，两者都可进入同一处理器；语义未知（接收分析（`rose_reverse/analysis/agate_receive_findings.md`））。
- 多个状态处理器把两个 hex 字符按十进制 `int.parse`，`0A`–`0F` 会抛 `FormatException`；这是 App 限制，第三方实现应按 radix 16 解析（接收分析（`rose_reverse/analysis/agate_receive_findings.md`））。
- EQ 的界面标签、`DeviceEQTypeModel` 字段值和 Sender 线值不一定一致：AGATE 的 `Rock(0)` 走 `setEqPop`（`01`），HIFI(1) 走 `setEqHifi`（`00`）；AGATE X 的 `Rock(0)`/`POP(1)` 同样分别走 Pop/Hifi。设备端最终预设含义未验证（AGATE 型号分析（`rose_reverse/analysis/agate_models_findings.md`））。
- 触控绑定模板只接受单个十进制动作码；动作码 ≥10 会拼出奇数长度 hex 字符串并解析失败（发送分析（`rose_reverse/analysis/agate_commands_findings.md`））。
- 触控绑定（Tag `05`）与触控开关（Tag `16`）是不同命令；AGATE/AGATE X/CERAMICS 的开关回调落到 thrower，CERAMICS-X/7034 也落到 thrower，EXPLORER 才有共享实现（分派表（`rose_reverse/analysis/i7_dispatch/table.tsv`））。
- AOT 去重会让 Blutter 类转储缺少方法体；判断回调是否存在必须看分派表，不能只看类文件（AGATE 接收分析（`rose_reverse/analysis/agate_receive_findings.md`））。
- 初始化发送的查询比型号界面支持的更多：例如 AGATE 会查 ANC/佩戴/提示音/等级/触控，但对应回调是 thrower；查询存在不代表型号有该能力。
- `F8Sender` 的共享方法不能直接算作型号支持；必须以配置构造函数和型号文档的控件表为准。
- `RDeviceComponentNoiseBarWidgetModel` 配置了 `NoiseLevelType` 列表不等于界面显示等级条：CERAMICS-X/7034 的 ANC/通透等级显示 flag 都是 false，等级只存在于接收解析（等级 flag 结论（`rose_reverse/analysis/legacy_capabilities.md:58`））。
- SPP `true` 不等于必然走 SPP；还要看平台、全局偏好和音频 Profile（传输分析（`rose_reverse/analysis/ceramics_transport.md`））。
- `otaUuid` 是 OTA 路由字段，不是控制 GATT Service；不要拿 `00007034-…` 连接控制通道（传输分析（`rose_reverse/analysis/ceramics_transport.md`））。
