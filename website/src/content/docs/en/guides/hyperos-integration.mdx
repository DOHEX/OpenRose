On HyperOS, OpenRose can run as an Xposed module and bring the earphones into the system UI:

- Connection prompts and earphone status shown through the system island and focus notifications.
- Earbud battery and noise mode switching in Fusion Device Center; "Additional Settings" can be set in Settings → System integration (系统集成) → Additional Settings entry (附加设置入口) to open OpenRose directly (defaults to the system page).
- Module control: the system Bluetooth process connects to the earphones, and OpenRose does not need to be open.
- Headset circulation (experimental): move the earphones from one HyperOS audio source device to another through Fusion Device Center.

:::caution[Verification status]
With an EarFree i5 and Xiaomi 14, Additional Settings opened OpenRose. On HyperOS 4.0.0.27, the focus card stayed visible with its island hidden. In module mode, the connection prompt and status notification appeared as a single battery island. Putting an earbud back in the case, switching audio between two devices, and HyperOS 3 still await hardware verification.
:::

## Requirements

- HyperOS 3 or 4
- A framework supporting libxposed API 102, for example LSPosed 2.2.0 or later

## Enable the module

<Steps>

1. Install OpenRose and connect the earphones as in [Getting started](../getting-started/).

2. Enable the OpenRose module in the Xposed framework, scoped to:
   - `com.android.bluetooth`
   - `com.xiaomi.bluetooth`
   - `com.milink.service`

3. Load the module: restart the phone, or tap Restart scopes (重启作用域) in the top right of OpenRose's Status (状态) page (requires root).

4. Back on the Status page, confirm that the module is ready.

</Steps>

## Control way

Choose the control way (控制方式) on the Settings page:

| Control way | Who connects to the earphones | Notes |
| --- | --- | --- |
| Ordinary control (普通控制, default) | The OpenRose app | No module needed; module-provided system integration is paused |
| Module control (模块控制) | The system Bluetooth process | Works from the first unlock after boot; OpenRose does not need to be open |

The choice is only an intent: whether the module is ready and whether the control connection is open are shown separately on the Status page.

When switching from module to ordinary control, OpenRose saves your choice and waits for the module to release the connection. If Status shows that release is pending, the app keeps retrying and takes over when release is confirmed. When switching to module control, OpenRose releases the ordinary control connection before saving the new choice.

## Persistent battery island and event prompts

In module mode, turn on focus notifications and the persistent battery island to keep battery levels visible in the status bar. Clear the display timings to keep that readout without connection or in-case prompts. To see only event prompts, turn off the persistent battery island and select the events you want.

## Focus notification tap target

On the Settings → System integration (系统集成) page, choose what tapping the earphone status notification opens: the OpenRose earphones page (default), the system headset page, RoseLink, or the quick panel. The quick panel is an OpenRose bottom sheet for switching noise mode, EQ preset, and game mode without opening the app; the OpenRose Quick Settings tile opens it too.

Options that cannot open right now (RoseLink not installed, or the system has no headset page) are disabled with the reason. If the chosen target later stops opening (for example, RoseLink was uninstalled), tapping the notification opens the OpenRose earphones page and says why at the top.

## Headset circulation (experimental)

Between HyperOS audio source devices, Fusion Device Center can circulate the earphones: they play on the other device, and OpenRose's control connection follows them there.

- Both devices need the OpenRose module enabled and module control selected; it is not offered under ordinary control.
- Circulation is not multipoint: with multipoint, the earphones stay connected to two devices at once.
- This has not been verified on real devices yet.

## Known limitations

- **Noise mode mapping**: the system only knows Off / ANC / Transparency. When the earphones are in wind-noise reduction, Fusion Device Center shows Off and the real mode is unchanged. Turn on "Off uses wind-noise reduction" (关闭降噪使用抗风噪) on the Settings → System integration (系统集成) page to make tapping Off write wind-noise reduction instead of normal mode.
- **Battery display**: when an earbud's battery is known but its charging state is unknown, Fusion Device Center does not show that battery; the case battery is not shown either.

When reporting system integration problems, include the Xposed framework version and the bridge status shown in diagnostics (reached from the Status page); see [Feedback](../feedback/).
