The desktop app provides BLE control through WinRT on Windows and through the system BlueZ service and D-Bus on Linux, without SPP, OTA, or system integration. The desktop has no control way to choose; the app holds the control connection directly.

:::caution[Verification status]
BLE control is implemented on both Windows x64 and Linux x64; full desktop hardware acceptance with the EarFree i5 is pending. See [Platform support](../../reference/platforms/) for verification status.
:::

## Install and connect

Desktop packages are published alongside the Android app; see [Getting started](../getting-started/#get-the-package).

<Tabs>
<TabItem label="Linux">

Linux x64 packages are published on [GitHub Releases](https://github.com/DOHEX/OpenRose/releases). For development builds, sign in to GitHub and download the `openrose-<version>-dev-<commit>-linux-x64` artifact from a successful [CI run](https://github.com/DOHEX/OpenRose/actions/workflows/ci.yml):

| File | For | Install example |
| --- | --- | --- |
| `openrose_<version>_amd64.deb` | Debian, Ubuntu 24.04+, and derivatives | `sudo apt install ./openrose_*.deb` |
| `openrose-<version>-1.x86_64.rpm` | Fedora and other RPM distributions | `sudo dnf install ./openrose-*.rpm` |
| `openrose-<version>-1-x86_64.pkg.tar.zst` | Arch Linux and derivatives | `sudo pacman -U ./openrose-*.pkg.tar.zst` |
| `openrose-<version>-x86_64.AppImage` | Other distributions, no installation | `chmod +x openrose-*.AppImage && ./openrose-*.AppImage` |

OpenRose requires **GTK 4.14 or later**. The native packages (`openrose`) declare dependencies on `bluez`, GTK 4.14+, D-Bus, GStreamer, and GLib, and install the `openrose` command alongside an **OpenRose** desktop entry. The AppImage does not bundle system libraries and expects GTK 4.14+, D-Bus, GStreamer, and BlueZ (with the Bluetooth service running) on the host.

Pair and connect the earphones in the system Bluetooth settings first. If the Status page shows “D-Bus 拒绝访问蓝牙” during discovery, check whether your desktop account has permission to use the system BlueZ service.

## Pair a phone and desktop

Enable module control on the phone. In the desktop settings, open **流转配对** (Handoff pairing) and show the pairing code. The remaining validity is shown below the code. Open the same setting on the phone, then scan the QR code or select the computer and enter its six digits. Both devices need to be reachable on the same local network, and the host firewall needs to allow the phone to reach TCP port 21871 on the desktop. Either device can remove the pairing in settings after confirming.

Find the headset card in My Earphones, the desktop tray, or the phone quick panel. **音源设备** (Audio source) shows which phone or computer is connected to this headset. While the headset is connected to the other device, you can adjust noise mode, ANC and transparency levels, EQ presets, and game mode remotely (depending on model capabilities) while the original source keeps playing. To use the headset on the other device, choose **改连这台电脑** (Move to this computer) or **改连这部手机** (Move to this phone) on that device. The original source disconnects first. If a call or an active headset microphone prevents the move, the card shows the reason.

## Tray and background control

Click the tray icon to see the primary headset with its audio source, battery pills, and noise modes, with inline actions such as **改连本机** (Move here) or **重新连接** (Reconnect) in the header. When multiple headsets are available, secondary headsets stay collapsed by default; choose **展开远端控制** (Expand remote controls) to adjust them.

If the audio source is unknown, choose **连接本机** (Connect here) to try connecting. The computer keeps its default sound output and shows it with a **声音设置** (Sound settings) shortcut in the panel. If battery readings and noise controls fail to return, choose **恢复耳机控制** (Restore headset controls). The audio connection stays on the computer.

On supported headsets, the panel also shows noise or transparency levels (when in the matching mode), game mode, and EQ presets by default. Open **设置 → 托盘面板控制项** (or choose **自定义** at the bottom of the panel) to toggle noise/transparency levels and choose or reorder game mode, EQ presets, spatial audio, and independent mic mode. Open OpenRose from the bottom of the panel for other settings.

On Linux, the tray icon uses D-Bus StatusNotifierItem and availability probing calls GLib's `gdbus`; GNOME also needs the AppIndicator extension (the tray is not verified on hardware under GNOME or KDE). On some desktops a left click opens the tray menu:

- **Background control (设置 → 后台控制, on by default) enabled and tray available**: closing the window only hides it and keeps the control connection; Quit in the tray menu ends it.
- **Background control off, or tray unavailable**: closing the window quits.

## Window rules for tiling compositors

On Linux desktops such as niri, Hyprland, or Sway, the tray panel is an ordinary window placed by the compositor, titled `OpenRose 托盘面板`. A window rule can float it near the tray, for example in niri:

```kdl
window-rule {
    match title="^OpenRose 托盘面板$"
    open-floating true
    default-floating-position x=12 y=12 relative-to="top-right"
}
```
