The desktop app provides BLE control through WinRT on Windows and through the system BlueZ service and D-Bus on Linux, without SPP, OTA, or system integration. The desktop has no control way to choose; the app holds the control connection directly.

:::caution[Verification status]
BLE control is implemented on both Windows x64 and Linux x64; full desktop hardware acceptance with the EarFree i5 is pending. See [Platform support](../../reference/platforms/) for verification status.
:::

## Install and connect

Desktop packages are published alongside the Android app; see [Getting started](../getting-started/#get-the-package).

<Tabs>
<TabItem label="Linux">

Linux x64 packages are published on [GitHub Releases](https://github.com/DOHEX/OpenRose/releases). For development builds, sign in to GitHub and download the `openrose-<version>-dev-<commit>-linux-x64` artifact from a successful [CI run](https://github.com/DOHEX/OpenRose/actions/workflows/ci.yml):

| File | For | Install example |
| --- | --- | --- |
| `openrose_<version>_amd64.deb` | Debian, Ubuntu 24.04+, and derivatives | `sudo apt install ./openrose_*.deb` |
| `openrose-<version>-1.x86_64.rpm` | Fedora and other RPM distributions | `sudo dnf install ./openrose-*.rpm` |
| `openrose-<version>-1-x86_64.pkg.tar.zst` | Arch Linux and derivatives | `sudo pacman -U ./openrose-*.pkg.tar.zst` |
| `openrose-<version>-x86_64.AppImage` | Other distributions, no installation | `chmod +x openrose-*.AppImage && ./openrose-*.AppImage` |

OpenRose requires **GTK 4.14 or later**. The native packages (`openrose`) declare dependencies on `bluez`, GTK 4.14+, D-Bus, GStreamer, and GLib, and install the `openrose` command alongside an **OpenRose** desktop entry. The AppImage does not bundle system libraries and expects GTK 4.14+, D-Bus, GStreamer, and BlueZ (with the Bluetooth service running) on the host.

Pair and connect the earphones in the system Bluetooth settings first. If the Status page shows “D-Bus 拒绝访问蓝牙” during discovery, check whether your desktop account has permission to use the system BlueZ service.

## Pair a phone and desktop

Enable module control on the phone. On the computer, open the **耳机流转** (Headset circulation) page in the sidebar and choose **开始流转配对** (Start circulation pairing) to show a six-digit code and QR code; the remaining validity is shown below the code. On the phone, open the circulation pairing entry, then scan the QR code or select the computer and enter its six digits. When the phone or another computer is the one starting circulation pairing, select the nearby peer it appears as under **流转配对新对端** (Pair a new peer) on the computer, enter its code, and choose **流转配对** (Circulation pairing). Both devices need to be reachable on the same local network, and the host firewall needs to allow the phone to reach TCP port 21871 on the desktop.

Peers that completed circulation pairing are listed under **已流转配对的对端** (Paired peers). Each card shows the peer name, the headset it currently holds, its battery, and whether it is online (**在线**) or offline (**不在线**); choose **刷新** (Refresh) to read it again, and an offline peer is read again automatically when it returns to the network. While the peer is online, the **降噪模式** (Noise mode) control on its card switches the noise mode remotely; the switch stays in progress until the peer's headset confirms it, and the audio keeps coming from the original source. Choose **取消流转配对** (Remove circulation pairing) to remove the peer.

When a peer holds the headset, its card offers **接到这台电脑** (Pull to this computer): the original source yields first, then the headset's audio connection and control move to this computer. The tray panel's peer card has the same button. Calls, active microphones, timeouts, or unreachable peers are reported directly, and the app never switches back automatically.

## Tray and background control

Click the tray icon to see the current headset with its name, connection state, battery, and noise modes. While connecting, choose **取消连接** (Cancel) to stop; when not connected, use the reconnect button to retry.

When this computer has no headset connected and a paired peer is using one, the tray icon switches to its remote state and the tooltip reads "headset name · source device name" with the battery, and the tray panel offers **接到这台电脑**; with several peers the first in paired order is shown. A local connection always takes precedence.

The tray panel and menu show the current system audio output and offer **打开声音设置** when a known sound settings program (such as `pavucontrol`, GNOME/KDE sound settings, or Windows Sound Settings) is installed. If battery readings and noise controls fail to return, choose **恢复耳机控制** (Restore headset controls). The audio connection stays on the computer.

On supported headsets, the panel also shows noise or transparency levels (when in the matching mode), game mode, and EQ presets by default. Open **托盘面板控制项** on the **托盘与后台** page in the sidebar (or choose **控制项设置** at the bottom of the panel) to toggle noise/transparency levels and choose or reorder game mode, EQ presets, spatial audio, and independent mic mode. Open OpenRose from the bottom of the panel for other settings.

On Linux, the tray icon uses D-Bus StatusNotifierItem and availability probing calls GLib's `gdbus`; GNOME also needs the AppIndicator extension (the tray is not verified on hardware under GNOME or KDE). On some desktops a left click opens the tray menu:

- **Background control (托盘与后台 → 后台控制, on by default) enabled and tray available**: closing the window only hides it and keeps the control connection; Quit in the tray menu ends it.
- **Background control off, or tray unavailable**: closing the window quits.

## Window rules for tiling compositors

On Linux desktops such as niri, Hyprland, or Sway, the tray panel is an ordinary window placed by the compositor, titled `OpenRose 托盘面板`. A window rule can float it near the tray, for example in niri:

```kdl
window-rule {
    match title="^OpenRose 托盘面板$"
    open-floating true
    default-floating-position x=12 y=12 relative-to="top-right"
}
```
