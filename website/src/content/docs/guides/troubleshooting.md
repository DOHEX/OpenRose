下面按界面上显示的提示整理，可以直接搜索看到的文字。没有找到对应情况时，请[反馈问题](../feedback/)。

## 找不到或连不上耳机

### “授予权限后可检测蓝牙并发现耳机”

OpenRose 还没有蓝牙权限。点界面上的授权按钮；如果之前拒绝过，系统会打开应用设置页，需要在那里手动授予。各权限的用途见[权限与隐私](../../reference/permissions/)。

### “请在系统设置中开启定位服务，以便此 Android 版本扫描蓝牙设备”

Android 8–11 扫描 BLE 设备时，系统要求定位服务处于开启状态。打开系统定位开关即可；OpenRose 不读取位置。

### “请先在系统设置中打开蓝牙，再回来搜索耳机”

系统蓝牙已关闭，打开后返回 OpenRose。

### 添加耳机时“暂未找到受支持的耳机”

- 打开耳机，进入配对模式，并让它靠近手机。
- 确认型号在[支持的耳机](../../reference/supported-earphones/)里。
- 同名耳机有多个硬件分支时，OpenRose 靠广播前缀区分；名称不足以确定分支时不会自动选择。

### 耳机页显示“未连接 · 耳机开盖后将自动连接”

OpenRose 的控制连接跟随系统音频连接：耳机在系统蓝牙里连上音频后，控制连接才会自动建立。先在系统蓝牙设置里连接耳机，可以点“无法连接？打开系统蓝牙设置”直接跳转。

### “连接未成功 · 请确认耳机已开盖并在附近”

控制连接没有建立。把耳机放回充电盒、合盖后重新打开，等系统音频重新连上。反复失败时，到耳机主页 → 设备详情 → 诊断与记录查看控制连接停在哪个阶段：

| 诊断中的原因 | 含义 |
| --- | --- |
| 耳机控制服务尚未就绪 | 耳机还没有提供控制所需的蓝牙服务，常见于刚连上时 |
| 设备状态订阅未完成 | 订阅耳机状态通知超时 |
| 首次状态读取发送未完成 | 首条读取命令没有发出去 |
| 首次读取尚未收到可用状态 | 命令已发出，但耳机没有回应 |

OpenRose 会自动重试这些情况。持续出现时请反馈，并附上诊断与记录页的内容。

## 设置与读数

### 某项设置在界面上找不到

可用的设置随型号和固件版本变化。没有研究证据的设置不会显示，也不会写入。显示“当前提供状态读取，控制设置尚未开放”的型号，目前只能查看状态。

### 设置后显示“回读不一致”或“确认超时”

OpenRose 每次写入设置后都会读回耳机的实际状态：

- **回读不一致**：耳机报告的值与请求的不同，设置没有生效。
- **确认超时**：没有收到耳机的确认，设置可能没有生效。

这两种情况对还没有真机验证的型号尤其有价值，请反馈，并附上诊断与记录页里的设置操作记录。

### 读数显示“设备未提供”或“当前状态未知”

“设备未提供”表示这台耳机或这个固件不报告该项；“当前状态未知”表示还没有读到可用的值。

## 后台控制

在“设置”页的后台控制卡片里查看状态：

| 提示 | 处理 |
| --- | --- |
| 已启用，尚未运行 | 正常：耳机下次连上音频或打开 OpenRose 时启动 |
| 缺少蓝牙权限，后台控制无法运行 | 点“授予蓝牙权限” |
| 系统限制了从后台启动，请打开 OpenRose 后重试 | 打开一次 OpenRose |
| 系统拒绝了前台服务启动，后台控制未运行 | 检查系统对 OpenRose 的后台与电量限制 |
| 运行通知：系统已隐藏，后台控制仍在运行 | 点“允许通知”恢复通知；不影响后台控制本身 |
| 自动唤起：尚未关联耳机或关联已被取消 | Android 12 及以上点“关联耳机” |
| 自动唤起：系统拒绝了设备在线监听 | 检查应用权限后点“重新关联耳机” |

显示“系统条件已配置”后，自启动和省电限制仍无法检测。HyperOS 等系统上，进程被回收后不能自动恢复时，点“应用设置（自启动、电量）”，允许自启动并取消电量限制。详见[后台控制](../background-control/)。

## HyperOS 模块

“状态”页会给出模块不可用的原因和下一步建议。需要重启作用域时，点“状态”页右上角的“重启作用域”（需要 root），或直接重启手机。

| 状态页显示 | 处理 |
| --- | --- |
| 系统模块未启用 | 在 Xposed 框架中启用 OpenRose 模块 |
| 系统模块暂不可用：尚未收到兼容框架服务 | 确认 Xposed 框架正在运行，并已在其中启用 OpenRose 模块。普通控制不受影响 |
| 系统模块暂不可用：框架服务 API 低于 102 | 把框架更新到支持 libxposed API 102 的版本，例如 LSPosed 2.2.0 或更新版本 |
| 建议勾选系统蓝牙（`com.android.bluetooth`）作用域 | 模块宿主没有找到：确认已勾选该作用域，然后重启作用域 |
| 系统模块已连接但未响应 | 宿主进程在运行但没有应答，重启作用域 |
| 系统蓝牙宿主拒绝了本应用 | 详情见“诊断与记录” |
| 与系统蓝牙宿主的连接已断开，正在自动重试 | 等待重试；反复出现时重启作用域 |

融合设备中心里降噪模式显示为“关闭”、电量不显示等现象属于已知限制，见 [HyperOS 系统集成](../hyperos-integration/#已知限制)。

## Linux 桌面版

| 提示 | 处理 |
| --- | --- |
| 未找到蓝牙适配器 | 确认电脑有蓝牙适配器且已被系统识别，例如运行 `bluetoothctl list` |
| 蓝牙适配器已关闭 | 打开蓝牙，例如 `bluetoothctl power on` |
| BlueZ 服务不可用 | 启动蓝牙服务，例如 `systemctl enable --now bluetooth` |
| D-Bus 拒绝访问蓝牙 | 当前用户无权访问 BlueZ，检查发行版对 `org.bluez` 的 D-Bus 访问策略 |
| BlueZ 运行环境缺少依赖 | 安装缺失的库；使用 AppImage 时尤其要检查 |
| 托盘图标：不可用 | 安装 `libsystemd`；GNOME 需要启用 AppIndicator 扩展 |

托盘面板在 niri、Hyprland、Sway 等桌面上位置不对时，见 [Linux 桌面版](../linux-desktop/#平铺式合成器的窗口规则)。
